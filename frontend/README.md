现已增加同项目管理端 `/admin`，沿用有戏浅色玫红风格。[使用与源码导读](../docs/admin-guide.md)、[后台接口](../docs/admin-api.md)、[验收记录](../docs/admin-validation.md)。原App公共外壳移至UserLayout，两端登录与布局分别管理。

日常使用可直接点击桌面“有戏-启动”／“有戏-关闭”，或项目根目录start-local.cmd／stop-local.cmd。关闭入口停止项目及独立中间件并保留数据。

端口更新：本机8082被QQ占用，完整运行版目前为 http://127.0.0.1:8083。一键脚本自动寻找空闲端口，以最终显示的地址为准；npm run dev在未设置API_PROXY_TARGET时读取本地运行记录中的实际端口，后端换端口后需重启前端开发服务。

**当前推荐使用完整运行版 http://127.0.0.1:8083（以启动脚本最终地址为准）**：在项目根目录双击 `start-local.cmd`，前端随后端 JAR 同源提供，独立库已开启交易。客服按要求显示“功能维护中”。详见[启动与实际验收边界](../docs/local-usable-version.md)。下文分阶段记录中8081指原库只读预览，不是完整交易入口。

第一阶段实现：首页图文分类导航与分类推荐、城市选择、演出搜索与分类筛选、分页、公开详情、场次票档选择及数量选择。首页只推荐尚未结束的演出，分类跳转保留当前城市。当前演示数据61条，均保留公开来源。第二阶段已实现邮箱登录与验证码注册、购票确认、异步结果恢复、订单列表与详情／取消、支付宝沙箱收银台。游客购票先登录，登录后回到确认页，明确确认后才提交申请。

## 启动

使用 Node.js 22.12+（本次验证为24）及 npm。在 `frontend` 目录执行：

```powershell
npm ci
npm run dev
```

访问 http://127.0.0.1:5173。默认代理 `/api` 到 `http://127.0.0.1:8082`。先按完整本地运行版说明启动后端。原库只读预览才使用8081，并保持交易和自动迁移关闭。

自定义后端地址：

```powershell
$env:API_PROXY_TARGET='http://127.0.0.1:8081'
npm run dev
```

生产构建执行 `npm run build`，部署 `dist/`。服务器需将 `/api/` 代理到后端、其他路由回退到 `index.html`；不能将 `/api/` 请求回退成 HTML。

## 验证

```powershell
npm test
npm run build
npm run test:e2e
```

端到端测试要求后端运行、已导入展示数据，默认使用本机 Edge。更换系统浏览器时调整 `playwright.config.ts` 的 `channel`。browse.spec.ts读取本地公开接口；trade.spec.ts使用受控接口响应，验证注册、幂等恢复、取消中间态、支付窗口和登录失效，不调用真实邮件或资金。后端真实链路由隔离集成测试验证。

运行依赖：Vue、Vue Router、Pinia、Axios、lossless-json（无损ID）、lucide-vue-next（图标）。构建与测试依赖：Vite、TypeScript、vue-tsc、Vitest、Playwright。前端依赖均是本次新增。

页面直接读取后端，没有自动启用的静态演出数据回退。后端不可用时展示错误并提供重试。远程海报不可用时显示标题占位；不会下载或存储第三方海报。


## 交易预览边界

当前8080后端仍使用交易关闭、迁移关闭、消费者关闭参数。页面已接入真实接口，提交时会展示“交易功能尚未启用”的拒绝受理结果；不生成假订单。原库的V5升级与开启交易需单独执行既有迁移验收流程，前端启动不会自动执行。

会话保存在sessionStorage，密码不持久化。购票申请编号及参数按用户ID保存在localStorage用于断网／刷新恢复；当前用户的服务端权限与库存才是判定依据。本地申请记录不作为支付成功凭据。

支付宝返回的页面HTML只提取受限表单参数，独立窗口提交到HTTPS沙箱网关。完整运行版同步回跳到 `/payment/return`，由服务端查单确认；也可回到原收银台查询结果。通知地址与人工付款的验证边界见完整运行版说明。


## 个人中心与客服

第三阶段提供个人资料、密码修改、收货地址、退款记录和智能客服。顶栏进入个人中心或客服；订单与账户页面共用导航。全部业务页面调用后端真实API，没有自动mock回退；测试中的接口拦截仅存在于Playwright用例。

资料保存仅更新资料列；登录邮箱只读。修改密码使用form请求体，不放URL或浏览器存储。默认地址不可删除，编辑保留默认标记。退款是最近100条只读记录，不提供后端不存在的退款申请。客服按用户隔离上下文，只开放查询工具；清空直接清服务器记忆，不调用模型；回复为纯文本。

2026-10-26本次预览后端为8081，因8080被其他项目使用。重启当前预览请在frontend目录设置：

```powershell
$env:API_PROXY_TARGET='http://127.0.0.1:8081'
npm run dev
```

本地预览5173读取真实本地后端；自动验收的账户写入、模型与资金使用受控响应／隔离容器，不会操作真实用户数据。客服实际可用性依赖本地AI配置和模型服务，错误会在页面显示；不把测试替身回复冒充真实模型验收。


## 整体验收

最新页面与接口映射、三种运行环境及未验收边界见[整体验收说明](../docs/frontend-acceptance.md)。常规npm run test:e2e覆盖全部公开浏览、账户下拉、交易与个人中心；320/768px布局与迟到响应验收在tests/acceptance.spec.ts。

真实业务API端到端由后端TradeApplicationIT.frontendBrowserCompletesRealPurchaseAndAccountJourney调用npm run test:e2e:live启动，不复用5173／原库后端。要求Java21、Docker和本机Edge；它启用一次性数据库交易、启动独立5183 Vite、模拟外部支付／邮件／模型，执行真实页面与后端写入。专用配置限制本机随机高端口及隔离标记，不是日常预览命令。测试产物test-results-live与普通测试输出分离并忽略。

生产构建可运行：

```powershell
$env:API_PROXY_TARGET='http://127.0.0.1:8081'
npm run build
npm run preview -- --port 4173 --strictPort
```

本地preview验证过SPA刷新、API代理、静态资源和登录保护；正式部署仍需按上文配置/api反向代理及index.html回退，不能把API错误回退为HTML。当前原库交易开关仍关闭。
