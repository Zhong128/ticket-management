## 发现与修复

- 初始管理地址会在路由就绪前挂载用户外壳，发送一次用户资料请求；入口改为等待首次路由后再挂载，两端请求与会话隔离测试通过。
- 旧schema的role VARCHAR(10)无法写入SUPER_ADMIN，隔离MySQL先报错；新增V6向前迁移扩宽至20字符，不修改旧迁移。真实超级管理员登录与后台流程随后通过。
- 用户编辑强制密码和全字段写回已替换为资料白名单DTO、具名列Mapper；拒绝敏感字段。管理员/SUPER_ADMIN保护覆盖单个、批量与SQL条件。
- 独立审查发现旧改密方法可能用快照覆盖管理员并发禁用，现仅更新密码列；真实MySQL验证status=0、角色与昵称均保留。
- 导航切换后运行标志不刷新，已增加重新核对并由专项测试先失败后通过。
- 手机长订单号溢出与共用order-facts样式冲突，已使用后台独立类名和换行；海报失败占位被挤成竖排也已修正，截图复验通过。
- 退款重试false不提示成功；订单取消后4仍显示确认中；库存调整异常不自动重发；离开列表后不再因新URL请求旧列表。

两类验收自身的问题已区分记录：接口拦截glob误匹配/src/api源码导致白页，已限定pathname以/api开头；临时formatter删除模板多语句分号导致Vue表达式错误，已提取具名方法。真实浏览器首次还遇到选择器与实际控件名称不一致，修正为可访问的combobox角色与真实字段标签后通过。这些失败不计入通过。

后端初次全量运行缺少已有Windows JDK21 Netty临时目录参数，出现27项环境错误；改用之前验证过的Mockito显式agent＋项目target临时目录后，106项完整通过。日志保留，不把早期错误描述为通过。
