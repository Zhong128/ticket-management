# 2026-10-20 隔离 JMeter 压测记录

## 测试边界

应用运行在本机 JDK 21 的 Spring Boot 测试 JVM；Testcontainers 使用全新的 MySQL 8、Redis 7、RabbitMQ 3.12 容器，不挂载项目原有数据卷。测试先在新库执行 V1～V3，再创建可售演出、票档和独立买家；每个买家的 Sa-Token 会话由项目原有登录组件写入隔离 Redis。JMeter 5.6.3 在同一台 Windows 机器上以 CLI 模式发 HTTP 抢票请求，使用 `reservation.jmx` 中的业务断言，付款、邮件、AI 均未真实调用。

JMeter 5.6.3 安装包取自 [Apache 发布归档](https://archive.apache.org/dist/jmeter/binaries/)，安装前使用同目录 SHA-512 文件校验。原始 JTL、HTML 报告、数据库摘要和运行日志保存在模块 `target/load-acceptance`，不提交 Git。

## 30 秒试跑

目标为每分钟 60 次、10 线程，独立账号 130 个。JMeter 实际 31 个样本，31 成功、0 失败，活跃发送窗口 29.92 秒，约 1.04 请求/秒；P50 42ms、P95 48ms、P99 287ms。隔离库有 31 笔预占和 31 笔订单，Outbox 未发布数为 0，库存范围与库存恒等式异常数均为 0。JTL 位于 `target/load-acceptance/20261020-210122/load.jtl`。

## 300 秒高负载尝试：未通过完整链路验收

目标为每分钟 6000 次、100 线程，独立账号 31000 个。JMeter 实际发送 22292 个样本，22292 个 HTTP/业务断言成功、0 失败；活跃发送窗口 302.61 秒，约 **73.67 请求/秒**，P50 1191ms、P95 2265ms、P99 5181ms。后段每 30 秒约 44～81 请求/秒，未稳定达到 100 请求/秒目标。

更关键的是，等待异步收敛后，隔离库虽有 22292 笔预占，却只有 6452 笔订单，`message_outbox` 中仍有 68490 条未发布事件；库存范围异常数和库存恒等式异常数均为 0。Maven 测试因 Outbox 未收敛而 **BUILD FAILURE**。因此“零 HTTP 错误”只能证明受理接口返回成功，不能证明售票闭环承载了这一负载。该轮邮件替身默认返回失败，产生通知重试并影响负载背景；后续已修正测试替身，另跑低速持续基线。原始诊断文件在 `target/load-acceptance/20261020-210336` 与 `target/jmeter-sustained-test.log`。

代码上 `OutboxPublisher` 当前单个定时任务逐条等待 RabbitMQ 发布确认；未发布事件大量积压且日志未见发布重试，说明发布侧处理能力需要专项分析。上述实现是可能的限制因素，**不能仅凭本轮数据断言它是唯一瓶颈**。

## 2026-10-21：300 秒低速基线

修正邮件替身后，以每分钟 120 次、20 线程的目标运行。JMeter 实际 601 个样本，601 个成功、0 失败；活跃发送窗口 299.89 秒，**2.00 请求/秒**，P50 27ms、P95 41ms、P99 59ms。隔离库有 601 笔预占、601 笔订单，Outbox 未发布数 0，邮件人工处理数 0，库存范围和恒等式异常数均为 0，`BUILD SUCCESS`。容器已回收。

该轮结束瞬间仍有 2 个订单邮件任务尚未完成，故它证明抢票、异步建单、Outbox 和库存完整收敛，不能据此声称所有邮件通知已发送。随后已将验收条件收紧为订单数等于预占数、邮件任务也须清零，并安排复验。原始文件在 `target/load-acceptance/20261021-003958` 与 `target/jmeter-sustained-2rps-test.log`。

## 2026-10-21：收紧断言后复验通过

仍以每分钟 120 次、20 线程持续 300 秒。JMeter 实际 601 个样本，601 成功、0 失败，活跃发送窗口 299.93 秒，**2.00 请求/秒**，P50 41ms、P95 72ms、P99 94ms。最终隔离库有 601 笔预占、601 笔订单，Outbox 未发布数 0，邮件待处理数 0、人工处理数 0，库存范围及恒等式异常数均为 0；`TradeLoadIT` 为 **BUILD SUCCESS**。测试容器已回收。原始文件在 `target/load-acceptance/20261021-004705` 与 `target/jmeter-sustained-2rps-final.log`。

因此本项目当前有一条经过 5 分钟验证的单机隔离环境基线：**2 次/秒、完整异步收敛**。每分钟 6000 次只是待整改目标，不能写为已达到的项目性能成绩。

复验后执行普通全量 `package`：93 项测试，91 项通过、0 失败、0 异常、2 项跳过，`BUILD SUCCESS`。两项跳过分别是原个人环境启动测试和需显式设置 `RUN_JMETER_LOAD=true` 的压测入口；完整 HTTP 应用集成测试的 3 项实际通过。日志位于模块 `target/jmeter-final-regression.log`。

## 结果解释

这是单机开发环境、单个应用实例的隔离功能与性能验收，不代表生产部署容量。需同时看实际发送速率、业务成功率、延迟分位数、Outbox 收敛和数据库库存恒等式；HTTP 200 中业务失败由 JMeter 断言计为失败。用户准备、应用启动、300 秒发压和异步收敛分别计时。未进行支付宝真实沙箱付款，也没有进行真实 SMTP 投递。
